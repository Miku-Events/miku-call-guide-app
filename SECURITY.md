# Security policy

## Supported version

Security fixes are applied to the current `main` branch and the production deployment. Historical
commits, forks, and unofficial deployments are not supported.

## Reporting a vulnerability

Do not open a public issue or pull request for a suspected vulnerability, exposed credential, or
private-data leak.

Use GitHub's **Report a vulnerability** flow in the repository Security tab (private vulnerability
reporting). If that flow is unavailable, email `seokjong.kim-1@student.uts.edu.au` with the subject
`Miku Call Guide security report`.

Include only the information needed to reproduce and assess the problem:

- affected URL, endpoint, or commit;
- impact and prerequisites;
- minimal reproduction steps or a proof of concept;
- whether any secret or personal information may have been exposed;
- a safe way to contact you for follow-up.

Do not access other users' information, degrade the service, or publish details before remediation.
The sole maintainer will coordinate next steps as capacity permits; no response-time or bounty is
promised.
